# Data Model: AI Chatbot Page

**Feature Branch**: `001-ai-chatbot`
**Date**: 2025-12-06

## Overview

This feature uses session-based, in-memory data managed by the AI SDK's `useChat` hook. No persistent storage or database is required.

## Entities

### Message

Represents a single message in the conversation.

| Field | Type | Description |
|-------|------|-------------|
| id | string | Unique identifier (auto-generated by AI SDK) |
| role | 'user' \| 'assistant' | Who sent the message |
| parts | MessagePart[] | Array of content parts |
| createdAt | Date | Timestamp when message was created |

### MessagePart

Represents a content segment within a message.

| Field | Type | Description |
|-------|------|-------------|
| type | 'text' \| 'reasoning' \| 'tool-call' \| 'tool-result' | Part type |
| text | string | Text content (for 'text' and 'reasoning' types) |

**Note**: For this MVP, only `type: 'text'` parts are rendered. Other types are ignored.

### UIMessage (AI SDK Type)

The full AI SDK message type used for API communication.

```typescript
interface UIMessage {
  id: string;
  role: 'user' | 'assistant' | 'system';
  parts: Array<{
    type: string;
    text?: string;
    [key: string]: unknown;
  }>;
  createdAt?: Date;
}
```

## State Management

### Client State (useChat hook)

| State | Type | Description |
|-------|------|-------------|
| messages | UIMessage[] | Array of all messages in conversation |
| status | 'streaming' \| 'ready' \| 'error' | Current chat status |
| input | string | Current user input (managed separately with useState) |

### Lifecycle

```
Page Load → Empty messages array
    ↓
User types → input state updates
    ↓
User submits → sendMessage({ text: input })
    ↓
User message added to messages array
    ↓
API call to /api/chat
    ↓
status = 'streaming'
    ↓
AI response streams in (message parts accumulate)
    ↓
Stream complete → status = 'ready'
    ↓
[Repeat from "User types"]
```

## Validation Rules

| Rule | Entity | Description |
|------|--------|-------------|
| Non-empty text | User message | Submit prevented if input is empty/whitespace |
| Role required | Message | Must be 'user' or 'assistant' |
| Parts required | Message | Must have at least one part |

## No Persistence

- Messages exist only in browser memory during the session
- Page refresh clears all messages
- No localStorage, sessionStorage, or database storage
- Each browser tab has its own independent conversation
